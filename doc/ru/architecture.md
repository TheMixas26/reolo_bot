# Архитектура

## Точка входа

Главная точка входа проекта: `dev/main.py`.

Она:

- создаёт `AIService`, `BackgroundScheduler` и общий `AppContext`;
- загружает текстовые ресурсы для включённых плагинов;
- регистрирует `CorePlugin` и плагины из списка `enabled_plugins`;
- перед запуском ботов выполняет `pytest tests/ -v`;
- запускает планировщик фоновых задач;
- создаёт отдельные потоки для основного, RPG- и банкового Telegram-ботов;
- запускает VK-listener, если VK-адаптер настроен;
- перезапускает polling Telegram-ботов при падении.

## Структура каталогов

```text
dev
├── analytics               простая аналитика и логирование событий
├── card_game               доменная логика карточной игры
├── config.py               локальный файл секретов и окружения
├── core                    AppContext и базовый core-плагин
├── database                SQLite, TinyDB и операции хранения
├── handlers                общие Telegram-обработчики
│   └── card_handlers       Telegram-слой карточной игры
├── main.py                 точка входа
├── plugin_template         шаблон нового плагина
├── plugins                 плагинные модули функций
├── posting                 модели, сервис публикации и адаптеры платформ
│   └── adapters            Telegram/VK-адаптеры публикации
├── settings.py             несекретные настройки
├── utils                   вспомогательные сервисы
└── varibles                текстовые ресурсы и служебные данные
```

## Контекст приложения

`dev/core/context.py` содержит `AppContext`. В него собираются:

- экземпляры Telegram-ботов;
- общий `APScheduler`;
- логгер и фабрика плагинных логгеров;
- объект `config`;
- Telegram-адаптеры;
- ID администратора, канала и служебного чата;
- `AIService`;
- `PostPublisher` и цель администратора.

Плагины получают `context` в методе `setup()` и через него регистрируют обработчики, задачи и зависимости.

## Плагины

Сейчас в `dev/main.py` подключены:

- `CorePlugin` — базовые команды `/start`, `/help`, `/changelog`;
- `PredlojkaPlugin` — предложка, модерация, теги, черновики и отложенные публикации;
- `BirthdaysPlugin` — дни рождения и уведомления;
- `WeatherPlugin` — прогноз погоды;
- `AIPlugin` — ответы через YandexGPT;
- `AdminUtilsPlugin` — бэкапы, команды ботов, рассылки и служебные действия;
- `BankPlugin` — банковые команды;
- `AchievementsPlugin` — достижения;
- `CalendarPlugin` — имперский календарь.

Обычная структура плагина:

```text
plugin.py      точка подключения
handlers.py    команды и callback/message handlers
jobs.py        фоновые задачи
service.py     бизнес-логика
db.py          локальный слой хранения, если нужен
texts.json     текстовые шаблоны
```

## Публикация

Публикация вынесена в `dev/posting/`.

- `models.py` описывает посты, платформы и цели публикации;
- `services.py` содержит `PostPublisher`;
- `runtime.py` собирает адаптеры из `dev/config.py`;
- `adapters/telegram.py` публикует в Telegram;
- `adapters/vk.py` публикует во VK.

По умолчанию активен Telegram. VK добавляется, если в конфиге есть `VK_TOKEN` и один из идентификаторов назначения: `VK_OWNER_ID` или `VK_GROUP_ID`.

## Основные данные

Основная SQLite-база создаётся по пути:

```text
dev/database/bot.sqlite3
```

В ней создаются, среди прочего, такие таблицы:

- `user_accounts`
- `birthdays`
- `rpg_players`
- `achievements`
- `user_achievements`
- `cards`
- `card_packs`
- `inventory`
- `card_events`
- `card_event_rewards`

Отложенные публикации и черновики используют отдельное TinyDB-хранилище:

```text
dev/database/scheduled_posts.json
```

## Фоновые задачи

Фоновые задачи регистрируются самими плагинами через `context.scheduler`.

Сейчас планируются:

- проверка очереди отложенных публикаций;
- ежедневные уведомления о днях рождения;
- персональные напоминания;
- поздравления именинников;
- прогноз погоды;
- резервные копии базы;
- обновление списка команд в Telegram;
- проверка достижений;
- проверка событий имперского календаря.

## Зависимости между модулями

Общий поток такой:

- `main.py` собирает контекст, подключает плагины и запускает процессы;
- `plugins/*` регистрируют функциональность;
- `handlers/` и `plugins/*/handlers.py` принимают события Telegram;
- `posting/` отвечает за публикацию в целевые платформы;
- `database/` хранит SQLite-данные и очередь отложенных публикаций;
- `card_game/` инкапсулирует механику карточной игры;
- `settings.py` хранит публичные настройки;
- `config.py` хранит секреты, токены, ID чатов и экземпляры ботов.

Из-за того, что `config.py` импортируется во многих модулях, этот файл остаётся важной точкой конфигурации проекта.
